## 坐标明牌

- 画布固定设计尺寸：`1726 × 980 px`。
- 原点：左上角 `(0, 0)`。
- 区域坐标使用百分比：`x` 向右，`y` 向下，`w` 为宽，`h` 为高。
- 像素换算：`xPx = x / 100 × 1726`，`yPx = y / 100 × 980`。
- 当前权威坐标来源只有 `planLabelsFromTopic()` 的返回值 `boardPlan`。
- Agent B 不应读取页面显示表格中的坐标，也不应自己重新推导；它读取 handoff 的 `boardPlan` 和 `zoneAnchors`。

## “是否唯一”答否的处理流程

当前项目没有发现既有责任表、图谱、留言板或 `xiaxia-symbols` 文件，因此本版先定义处理规则：

1. 停止继续新增实现。
2. 指定唯一权威对象，保留其名称和来源依据。
3. 其他副本改为读取权威对象；不能读取的副本删除或改名为展示/缓存对象。
4. 全局搜索旧名称和旧字段，逐处改为权威字段。
5. 在本表“来源依据·受什么影响”列记录修改位置和理由。
6. 在下方变更记录追加一行，不覆盖历史记录。
7. 运行 lint/build，并逐项对照本表自审。

| 冲突 | 现状 | 唯一真相 | 处理要求 |

| 第 1 次识别是否查询知识 | `vite.config.js` 仍加载并注入 CSV、MD，提示词仍有旧知识检索段落 | 第 1 次只识别和落位 | 删除第 1 次请求中的 CSV/MD 注入和知识检索字段 |

| 截图缓存是否进入 handoff | 二次 API 返回 `cachePath`，但 `buildStep1Handoff` 没有 `cachePath` 字段 | `previewDataUrl` 是图片事实；`cachePath` 是可选审计路径 | 明确是否把 `cachePath` 纳入 handoff；若纳入，只由 `boardKnowledgeQuery` 产生 |
| Agent B 知识点来源 | `src/agent-b-v2/service.js` 仍可回退 `selectAgentBRelatedKnowledge` 的 n-gram | `handoff.relatedKnowledge` | 删除回退；没有 handoff 知识点时明确为空，不准二次本地推断 |
