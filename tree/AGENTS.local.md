# Project memory

## Notes 做事请思考  不要随便敷衍的态度

## 核心原则
1. 极简但完整：每个字都有价值，无冗余。少即是多，最大化复用现有资源但务必在做好代码隔离的基础上(若文件较多请用软连接和物理隔离)
思考如何通过最简的路径达到要求(最小新增，高效复用，核心目标明确)
严格遵守代码模块化思路！复用的地方用模块调用为优先策略，
禁止代码膨胀
2. AI友好：使用结构化、可执行的语言。设计系统、结构或工程项目前，先到 GitHub 等可信来源检索成熟框架、系统模板、可复用模块；严禁手搓，只有在无现成可用方案时才自行实现。
3. 严谨代码膨胀：能复用的公共 CSS、模块、函数等必须纳入公共引用管理，禁止重复复制。
4. 能用图就不要一堆 md：维护两张图——系统全景设计规划图（节点带关键词）、施工进展图。上下文 = 图 + 变更 tree。
5. 任何修改，必须记录变更树；没落下痕迹就等于没做。
6. 没有验证过的代码不要说好了；以代码实际为真相。
7. 标准工业化：优先使用成熟框架代码，禁止盲目手搓，避免团队无法交接与高昂维护成本。
8. 禁止过度设计、自我造词；字段、参数、出参入参必须清晰可溯源。
9. 缓存 + 增量阅读 +（图 + tree 替代上下文）。
10. 一个问题错误超过五次，马上停下，逆向思考断裂点。学会主动看看自己有什么skills可以帮助自己，多元化视角自适应身份叠加态不少于2个视角模拟流程找到不和理的点（举例：如果是用户视角，使用流程？  如果是产品经理视角，要怎么设计？  ）
