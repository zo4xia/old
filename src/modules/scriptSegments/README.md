# scriptSegments

`scriptSegments` 是 `<br>` 智能断句的只读预览模块。

2026-05-17 后，用户主路径优先使用 `ScriptSegmentWorkbench`，把“送阿里云前分段 / A 轨音频段 / C 素材候选提示”压成同一块生成前确认区。

`ScriptSegmentPreview` 仍保留为轻量只读预览，但不要再把规则说明散落到多个页面里。

## 真相边界

- 唯一分段真相仍是口播稿里的 `<br>`。
- 本模块只调用 `splitScriptIntoTtsSentenceUnits()`，不重新实现切分规则。
- 页面上的分片高亮只是 `<br>` 的可视化投影。
- `<b>...</b>` 是旧合同里的板书候选投影，不参与 TTS 分段；新 Agent 主路径优先使用 rows 的 `boardSlice`，并把它视为 C 素材候选。

## 分片口径

- `<br>` 等于一次明显语音停顿和一次 A 轨生成切片，不是标点分句。
- 分片数量不设硬性上限，以讲解步骤清楚、时间轴区间清楚、A/B/C 对齐清楚为准。
- 每个 `<br>` 分片应对应一个清楚的 A 轨时间区间；普通解释可以合并，核心公式和板书节点可以单独成段。
- 核心公式、核心算式、关键变形、最终答案这类 C 素材候选节点必须独立切片，方便 A 轨停顿和 B 寿命窗口对齐。
- 普通解释、过渡语、生活例子、鼓励语尽量合并，不要频繁切。

## 模板范式

`<br>` 位置由口播稿决定，但 Agent 生成时应优先按下面的 A/B 形状组织：

- `A1`：开场与读题，必要时把题目原式放进 `<b></b>`。
- `A2`：观察与方法，说明题型、第一步看什么、为什么这样做。
- `A3..An`：核心计算步骤，每个核心公式、核心算式或关键变形单独成段，段内用 `<b></b>` 标出板书内容。
- `A末`：最终答案、化简检查、简短鼓励；最终答案必须进入 `<b></b>`。

简单题优先 4-8 段，一般题尽量不超过 10 段；这只是生成模板，不是程序切分的新真相。

## 时间轴口径

- 一个 `<br>` 分片进入 A 轨后，对应一段从开始时间到结束时间的语音区间。
- 这个分片里的 `<b>...</b>` 或 rows `boardSlice` 落在同一个 A 轨区间内，成为 C 素材候选；A 返回真实时长后再生成 B 寿命窗口。
- B 寿命窗口可以在这个区间内再细调出现时间和时长，但不反过来改变 A 轨文本分段真相；超出 A 区间的 B 尾巴只让 C 静态留场。

## UI 口径

- `ScriptSegmentWorkbench` 面向不懂技术的用户，优先显示“会生成几段 A 轨音频”和“有几个 C 素材候选”。
- 分段列表里的每一行都是 `<br>` 分片的投影。
- “调整文稿”只能回到正式文稿编辑入口，不能在 workbench 内另存一份分段。
- 以后做拆分/合并按钮时，也必须只修改原始 `scriptText.summary` 里的 `<br>`。

## 不负责

- 不请求阿里云。
- 不写 `TeachingProject`。
- 不生成 B 轨事件。
- 不保存 project.json。
- 不创建第二套 segmentation JSON 真相。
